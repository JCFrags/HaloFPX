# Project Lead Control

Purpose: maintain a concise management view of the multiday HaloFPX effort
without duplicating implementation evidence or micromanaging the worker.

Canonical records:

- `OBJECTIVES.md` — end state and non-negotiable gates.
- `CURRENT_STATUS.md` — latest verified management snapshot.
- `MONITORING.md` — cadence and intervention policy.
- `DECISIONS.md` — project-lead decisions and steering history.
- `monitor-state.json` — machine-readable worker/commit cursor.

The lead observes first, checks repository and node evidence, and intervenes
only when the current state demonstrates drift, unsafe behavior, repeated
blockage, or a missing decision. Worker commentary alone is not sufficient
evidence for promotion.

> Not the final product. Constantly review it, make improvement suggestions,
> refine it, and update it.
