## License and provenance disposition

- Any **MP** row must retain commit-level attribution and a reviewer-approved notice record. Any **CR** row must be implemented without copying expressive source from the GPL wrapper.
- The direct cherry-pick roster remains empty. A merge commit or copied file is not evidence that its dependency closure, authorship, or target behavior is acceptable.

## Deletion and omission hazards

1. Omitting the corrective commits after `6a0db500ca1058e06a232c02c50eb5df56b0d151` can reintroduce cross-slot, hybrid, MTP, overlap, restart, and POSIX defects demonstrated by the donor history.
2. Removing ROCmFPX `server_prompt_cache` cleanup semantics changes an explicitly ephemeral per-run cache into undeclared persistence; persistence needs a new provider/catalog contract, not deletion of the destructor.
3. Persisting target context without draft and required speculative state can accept a logically invalid MTP/Eagle boundary. Invalid or missing state must cause a miss/recompute.
4. Ignoring destination sequence IDs can restore state into the wrong slot. Cross-slot fixtures are mandatory.
5. Accepting a request-body user identifier as authorization creates cross-tenant exposure. Tenant scope must be derived from authenticated server policy.
6. Disabling fsync may be an explicitly labeled benchmark mode, but it cannot satisfy the durable-cache contract.
7. Reusing donor compatibility hashes without a target-owned manifest can accept stale or incompatible state. Model, tokenizer/template, build/ABI, architecture, cache-policy, speculative, and topology identities remain explicit design work.
8. A failed disk load must leave the destination slot clean or force recomputation. Deleting only the disk record is not proof that partially loaded context was rolled back.
