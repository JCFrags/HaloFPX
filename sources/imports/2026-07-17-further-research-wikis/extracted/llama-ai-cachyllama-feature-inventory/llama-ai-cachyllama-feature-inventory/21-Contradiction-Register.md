# Contradiction and implementation-gap register

This register separates documented intent from behavior actually visible at the pinned commits.

| ID | Topic | Documented or implied behavior | Pinned implementation evidence | Assessment |
|---|---|---|---|---|
| C-01 | Anonymous concurrency | User-isolation design/server documentation describe anonymous requests as a shared bucket subject to the per-user cap. | `server-context.cpp` checks and increments only non-empty user IDs and states anonymous traffic is constrained only by global parallelism. [E-080](20-Evidence-Index.md#e-080), [E-084](20-Evidence-Index.md#e-084), [E-085](20-Evidence-Index.md#e-085) | Documentation is not satisfied. Reject the pinned anonymous policy. |
| C-02 | User cache statistics | The architecture exposes per-user cache namespaces and cache statistics. | `get_stats()` aggregates anonymous conversation maps but omits user maps. [E-060](20-Evidence-Index.md#e-060), [E-064](20-Evidence-Index.md#e-064) | User cache usage is underreported. |
| C-03 | User cache tier aging | Turn completion is expected to age cache entries through tiers. | The pinned turn path advances anonymous wrappers but omits user wrappers. [E-064](20-Evidence-Index.md#e-064) | User cache residency can diverge from policy. |
| C-04 | Conversation limit scope | The maximum-conversation control is presented as a cache capacity control. | Anonymous and user cache maps are managed separately; oldest-directory removal is not one global/tenant byte quota. [E-061](20-Evidence-Index.md#e-061), [E-065](20-Evidence-Index.md#e-065) | Capacity semantics are ambiguous and mtime-based. |
| C-05 | System-boundary awareness | The cache accepts a chat-template hint and is described as system-prompt caching. | Boundary detection decodes token text and searches marker strings; the template hint is not used structurally. [E-054](20-Evidence-Index.md#e-054) | False boundaries can cache user content. |
| C-06 | Persistence durability | Optional fsync suggests durable checkpoint publication. | Primary checkpoints are written directly to final names rather than committed through temporary files and rename. [E-034](20-Evidence-Index.md#e-034) | fsync does not provide transactional publication. |
| C-07 | Configuration defaults | Source, server documentation, and parent profile each present defaults. | Source hot window is 16,384 and cold count is 0; parent uses 4,096 and 32; checkpoint-step documentation differs from source fields. [E-006](20-Evidence-Index.md#e-006), [E-022](20-Evidence-Index.md#e-022), [E-024](20-Evidence-Index.md#e-024) | Effective configuration depends on layer; schema generation is required. |

## Resolution policy

For ROCmFPX, source behavior wins over documentation when determining compatibility, but the target design should not perpetuate a known discrepancy. Every configuration default and user-visible claim should be generated from one schema or tested against the implementation.
