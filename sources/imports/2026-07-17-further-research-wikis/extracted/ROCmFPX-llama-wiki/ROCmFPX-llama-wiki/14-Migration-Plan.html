Migration plan

Audit snapshot: fork a5605a72768c6562241b248e268e33dc92787394; upstream 86d86ed4396b4130922f7b9af26e3d9fc11a591b; inventory date 2026-07-17.
Decision vocabulary: RETAIN = capability/ABI must survive; REFRESH = preserve capability but re-port onto current upstream; RETIRE = remove the fork patch and use upstream or archive it. S-FORK-HEAD S-UP-HEAD

Phase 0 — freeze compatibility contracts

Before touching upstream files:

  1. Record type IDs and sizeof(block_*) assertions.
  2. Generate golden quantize/dequantize vectors for every format and endpoint.
  3. Capture GGUF load/round-trip fixtures.
  4. Capture CPU/HIP/Vulkan operation matrices and real-model coherency prompts.
  5. Capture strict-MTP target-equivalence and cache-restart fixtures.

These contracts exist across the fork’s enum, block headers, reference implementations, backend tests, and server tests. S-QT-ENUM-FORK S-ROCMFP4-H S-ROCMFPX-H S-ROCMFP2-TEST S-BACKEND-TEST S-C-7D7 S-SERVER-TEST

Phase 1 — establish a clean upstream base

Create a branch at 86d86ed4396b4130922f7b9af26e3d9fc11a591b and verify the unmodified upstream build/test matrix for the intended CPU, HIP, Vulkan, server, and RPC configurations. Do not begin by merging the ROCmFPX tree into it. S-UP-HEAD S-AMD-LLAMA

Phase 3 — delete superseded patch families

Remove the fork copies of HY3/model graph, fork-private MTP APIs, split-export converter patch, WebUI/parser/Jinja/Apple repairs, Hexagon/OpenCL/WebGPU snapshots, and duplicate draft PRs. S-UP-PR25395 S-EXT-UP S-UP-SPLIT-MTP S-C-807 S-C-FF8 S-C-01D S-PR29 S-PR30

Phase 4 — qualification

The release gate should require:

  • CPU golden vectors and quantizer round trips;
  • HIP and Vulkan operation matrices;
  • packed FP6 unaligned copy;
  • Strix real-model coherency;
  • strict MTP target equivalence;
  • disk-cache restart/corruption tests;
  • RPC target+draft multi-context and local-iGPU-plus-remote-device tests;
  • performance comparison against the current fork with full environment manifest.

The evidence roots for these gates already exist in the fork and upstream fixes. S-BACKEND-TEST S-C-62F S-ROCMFPX-CI S-C-7D7 S-SERVER-TEST S-RPC-MTP-FIX S-RPC-IGPU-FIX

Phase 5 — patch governance

Maintain three explicit upstream relationships:

  • UPSTREAM_BASE — one pinned llama.cpp SHA;
  • ROCMFPX_FORMAT_ABI — versioned extension ABI and golden vectors;
  • ROCMFPX_PATCHSET — small ordered commits with one subsystem per patch.

Close superseded draft PRs and require every future shared-file patch to state whether it is format-owned, hardware-owned, policy-owned, or a temporary upstream backport. S-COMPARE S-PR29 S-PR30 S-UP-HEAD
